# 农资管理系统 - 前端开发规划

## 一、项目概述

### 1.1 技术栈

| 技术 | 说明 |
|------|------|
| Vue 3 | 前端框架（Composition API） |
| Vite | 构建工具 |
| Vue Router 4 | 路由管理 |
| Pinia | 状态管理 |
| Element Plus | UI 组件库 |
| Axios | HTTP 请求库 |
| ECharts | 数据可视化图表库 |

## 三、开发阶段规划

### 第一阶段：基础设施与公共层（预计 2 天）

> **目标：** 搭建可复用的前端基础架构，为后续页面开发提速。

#### 3.1 API 接口层完善

为后端所有 Controller 创建对应的前端 API 模块：

| 文件 | 对应后端 Controller | 主要接口 |
|------|---------------------|----------|
| `api/user.js` | `UserController` | 分页查询、新增、编辑、删除、重置密码、角色分配 |
| `api/product.js` | `ProductController` | 分页查询、新增、编辑、删除、详情 |
| `api/category.js` | `CategoryController` | 列表、新增、编辑、删除、树形结构 |
| `api/unit.js` | `UnitController` | 列表、新增、编辑、删除 |
| `api/supplier.js` | `SupplierController` | 分页查询、新增、编辑、删除 |
| `api/customer.js` | `CustomerController` | 分页查询、新增、编辑、删除 |
| `api/purchase.js` | `PurchaseOrderController` | 订单列表、创建、详情、审核、取消 |
| `api/sales.js` | `SalesOrderController` | 订单列表、创建、详情、审核、取消 |
| `api/inventory.js` | `InventoryController` | 库存列表、库存日志、盘点、报损 |
| `api/dashboard.js` | `DashboardController` | 统计概览数据 |
| `api/report.js` | `ReportController` / `SalesStatsController` | 销售报表、进货报表、导出 |

#### 3.2 公共组件库 (`components/`)

| 组件 | 文件名 | 说明 |
|------|--------|------|
| 搜索栏 | `SearchBar.vue` | 封装表格上方的搜索表单区域，支持重置 |
| 状态标签 | `StatusTag.vue` | 根据状态值显示不同颜色的 Tag |
| 空状态 | `EmptyState.vue` | 数据为空时的占位提示 |
| 详情描述列表 | `DetailDescriptions.vue` | 基于 el-descriptions 的详情展示组件 |
| 确认操作按钮 | `ConfirmButton.vue` | 带二次确认的操作按钮 |
| 分页表格 | `PagedTable.vue` | 封装 el-table + el-pagination 的分页表格 |
| 图片上传 | `ImageUpload.vue` | 封装商品图片上传逻辑 |

#### 3.3 组合式函数 (`composables/`)

| 函数 | 文件名 | 说明 |
|------|--------|------|
| 分页查询 | `usePagedQuery.js` | 封装分页参数、查询、翻页逻辑 |
| CRUD 操作 | `useCrud.js` | 封装增删改查通用流程（加载、提交、删除确认） |
| 表单弹窗 | `useFormDialog.js` | 封装弹窗表单的打开、提交、关闭逻辑 |
| 文件导出 | `useExport.js` | 封装文件下载/Excel 导出逻辑 |

## 七、接口响应格式约定

后端统一返回格式：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { ... }
}
```

分页查询返回格式：

```json
{
  "code": 200,
  "message": "查询成功",
  "data": {
    "records": [...],
    "total": 100,
    "pageNum": 1,
    "pageSize": 10
  }
}
```

> 前端 `request.js` 的响应拦截器已处理 `code !== 200` 的错误情况。

## 九、注意事项

1. **API 对接原则：** 先完成后端接口联调再美化 UI，优先保证功能可用
2. **组件复用：** 公共组件在第一阶段完成后，后续页面应优先使用
3. **错误处理：** 所有 API 调用必须有 try-catch，给用户友好提示
4. **表单验证：** 提交前必须做前端校验，减少无效请求
5. **Git 提交：** 每完成一个功能模块即提交一次，提交信息遵循 Conventional Commits 规范
6. **浏览器兼容：** 目标支持 Chrome 90+、Edge 90+、Firefox 88+
7. **代码风格：** 使用 Composition API + `<script setup>` 语法，保持一致性
