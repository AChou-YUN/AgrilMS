# 阶段5：销售与客户管理

## 一、阶段目标

实现客户（农户）信息管理和销售业务全流程，包括客户的增删改查、销售开单、自动扣减库存、销售单打印（模拟）、按时间段统计销售额等功能。

**预计工期：2天**

**前置条件：** 阶段4完成，进货与库存管理系统已就绪。

---

## 二、功能需求

### 2.1 客户（农户）管理
- 零售商或管理员可添加、编辑、删除客户信息
- 客户信息包含：姓名、联系方式、地址、购买偏好、备注
- 客户列表支持按姓名搜索
- 客户购买历史关联查询

### 2.2 销售开单
- 零售商对农户进行销售开单，包含以下信息：
  - 选择客户（可选，支持散客）
  - 选择农资产品（支持多产品批量销售）
  - 填写每种产品的销售数量和售价（默认取产品参考售价）
  - 选择付款方式（现金/微信/支付宝/赊账）
  - 选择销售日期
  - 填写备注
- 系统自动生成唯一销售单号（格式：`SO` + 日期 + 序号，如 `SO20260521001`）
- 自动计算每项小计金额和总金额
- 提交时校验库存是否充足
- 销售成功后自动扣减对应产品库存
- 记录库存变动日志

### 2.3 销售单管理
- 销售单状态管理：已完成/已退货/部分退货
- 支持退货处理（整单退货或部分退货）
- 退货时自动增加库存
- 已退货的销售单标记状态

### 2.4 销售单打印（模拟）
- 模拟打印功能，生成销售单打印内容
- 包含：单号、日期、客户信息、商品明细、合计金额、收款方式等

### 2.5 销售统计
- 按时间段（日/月/年）统计销售总额
- 按时间段统计销售量
- 按产品或分类统计销售排行
- 按客户统计购买金额

### 5.4 核心业务逻辑

**销售开单流程：**
1. 校验客户是否存在（如有指定客户）
2. 校验所有产品是否存在且上架
3. 校验每个产品的库存是否充足：`current_stock >= quantity`
4. 生成唯一销售单号
5. 计算每个明细的小计和总金额
6. 插入销售单主表和明细表
7. 遍历明细，对每个产品扣减库存：`current_stock -= quantity`
8. 记录库存变动日志（变动类型：SALE）
9. 返回销售单详情

**退货处理流程：**
1. 校验销售单状态
2. 如果是整单退货：
   a. 遍历所有明细，增加库存
   b. 更新销售单状态为"已退货"
3. 如果是部分退货：
   a. 校验退货数量不超过已售数量
   b. 增加对应库存
   c. 更新明细的退货数量
   d. 更新销售单状态为"部分退货"
4. 记录库存变动日志（变动类型：RETURN）

**销售单号生成规则：**
```java
// 格式：SO + yyyyMMdd + 3位序号
String orderNo = "SO" + LocalDate.now().format(DateTimeFormatter.ofPattern("yyyyMMdd"))
                + String.format("%03d", sequence);
```

**关键事务操作：**
- 创建销售单（主表+明细+扣减库存+记录日志，原子操作）
- 退货处理（更新状态+增加库存+记录日志，原子操作）

## 六、MyBatis XML 关键SQL

### 6.1 销售单列表查询

```xml
<select id="selectByPage" resultType="SalesOrderVO">
    SELECT so.*, 
           c.name AS customer_name, c.phone AS customer_phone,
           u.real_name AS operator_name
    FROM sales_order so
    LEFT JOIN customer c ON so.customer_id = c.id
    LEFT JOIN sys_user u ON so.user_id = u.id
    <where>
        <if test="orderNo != null and orderNo != ''">
            AND so.order_no LIKE CONCAT('%', #{orderNo}, '%')
        </if>
        <if test="customerId != null">
            AND so.customer_id = #{customerId}
        </if>
        <if test="status != null">
            AND so.status = #{status}
        </if>
        <if test="paymentMethod != null">
            AND so.payment_method = #{paymentMethod}
        </if>
        <if test="startDate != null">
            AND so.order_date >= #{startDate}
        </if>
        <if test="endDate != null">
            AND so.order_date <= #{endDate}
        </if>
    </where>
    ORDER BY so.create_time DESC
</select>
```

### 6.2 销售单明细查询

```xml
<select id="selectItemsByOrderId" resultType="SalesItemVO">
    SELECT soi.*, p.name AS product_name, p.specification, un.name AS unit_name
    FROM sales_order_item soi
    LEFT JOIN product p ON soi.product_id = p.id
    LEFT JOIN unit un ON p.unit_id = un.id
    WHERE soi.order_id = #{orderId}
</select>
```

### 6.3 销售统计查询

```xml
<!-- 按日统计 -->
<select id="selectDailyStats" resultType="SalesStatItem">
    SELECT DATE_FORMAT(order_date, '%Y-%m-%d') AS date,
           SUM(total_amount) AS amount,
           COUNT(*) AS count
    FROM sales_order
    WHERE status != 2
      AND YEAR(order_date) = #{year}
      AND MONTH(order_date) = #{month}
    GROUP BY order_date
    ORDER BY order_date
</select>

<!-- 按月统计 -->
<select id="selectMonthlyStats" resultType="SalesStatItem">
    SELECT DATE_FORMAT(order_date, '%Y-%m') AS date,
           SUM(total_amount) AS amount,
           COUNT(*) AS count
    FROM sales_order
    WHERE status != 2
      AND YEAR(order_date) = #{year}
    GROUP BY YEAR(order_date), MONTH(order_date)
    ORDER BY date
</select>

<!-- 产品销售排行 -->
<select id="selectProductRanking" resultType="SalesRankingVO">
    SELECT p.id AS product_id, p.name AS product_name,
           pc.name AS category_name,
           SUM(soi.quantity) AS total_quantity,
           SUM(soi.subtotal) AS total_amount
    FROM sales_order_item soi
    JOIN sales_order so ON soi.order_id = so.id
    JOIN product p ON soi.product_id = p.id
    LEFT JOIN product_category pc ON p.category_id = pc.id
    WHERE so.status != 2
      AND so.order_date BETWEEN #{startDate} AND #{endDate}
    GROUP BY p.id, p.name, pc.name
    ORDER BY total_amount DESC
    LIMIT #{limit}
</select>
```

## 九、注意事项

1. 销售开单必须在同一个事务中完成（创建单据+扣减库存+记录日志），确保数据一致性。
2. 库存校验和扣减需要考虑并发问题，建议使用数据库乐观锁或 `SELECT ... FOR UPDATE`。
3. 退货时需校验退货数量不超过原销售数量，且同一明细不能重复退货超过已售数量。
4. 销售统计中"已完成"状态的单据才计入统计，已退货的不计入（或按负数处理）。
5. 客户管理中的散客（无客户信息）场景需要特殊处理，customerId 允许为空。
6. 销售单打印功能后端只提供数据接口，实际打印排版由前端实现。
7. 大写金额转换可使用工具类实现（如 Hutool 的 NumberChineseFormatter）。
