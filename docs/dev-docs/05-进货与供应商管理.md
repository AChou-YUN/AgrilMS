# 阶段4：进货与供应商管理

## 一、阶段目标

实现供应商信息管理和进货业务全流程，包括供应商的增删改查、进货单的录入与管理、进货自动增库存、进货历史记录查询等功能。

**预计工期：2天**

**前置条件：** 阶段3完成，农资产品管理和库存表已就绪。

---

## 二、功能需求

### 2.1 供应商管理
- 经销商或管理员可添加、编辑、删除供应商信息
- 供应商信息包含：名称、联系人、电话、地址、信用等级（1-5级）、银行账号、备注
- 供应商列表支持按名称搜索、按信用等级筛选
- 供应商启用/禁用状态管理
- 删除供应商前检查是否有关联的进货单

### 2.2 进货单管理
- 经销商录入进货单，包含以下信息：
  - 选择供应商
  - 选择农资产品（支持多产品批量进货）
  - 填写每种产品的进货数量和进价
  - 选择进货日期
  - 填写备注
- 系统自动生成唯一进货单号（格式：`PO` + 日期 + 序号，如 `PO20260521001`）
- 进货单提交后自动增加对应产品库存
- 进货单状态管理：待确认 → 已入库 → 已取消
- 已入库的进货单不可修改或删除
- 取消进货单时需回退库存

### 2.3 进货历史查询
- 支持按供应商、进货日期范围、进货单号搜索
- 查看进货单详情（含所有明细产品）
- 统计某时间段内的进货总额

### 5.3 核心业务逻辑

**新增进货单流程：**
1. 校验供应商是否存在且启用
2. 校验所有产品是否存在且上架
3. 生成唯一进货单号
4. 计算每个明细的小计和总金额
5. 插入进货单主表和明细表
6. 状态设为"待确认"（0）

**确认入库流程：**
1. 校验进货单状态必须为"待确认"
2. 更新进货单状态为"已入库"（1）
3. 遍历明细，对每个产品：
   a. 更新或插入库存表（inventory）：`current_stock += quantity`
   b. 记录库存变动日志（inventory_log）：变动类型为 `PURCHASE`

**取消进货单流程：**
1. 如果当前状态为"待确认"：直接改为"已取消"
2. 如果当前状态为"已入库"：
   a. 遍历明细，对每个产品减少库存：`current_stock -= quantity`
   b. 记录库存变动日志（变动类型为 `PURCHASE`，数量为负）
   c. 更新状态为"已取消"

**进货单号生成规则：**
```java
// 格式：PO + yyyyMMdd + 3位序号
String orderNo = "PO" + LocalDate.now().format(DateTimeFormatter.ofPattern("yyyyMMdd"))
                + String.format("%03d", sequence);
```

**关键事务操作（使用 `@Transactional`）：**
- 创建进货单（主表+明细，原子操作）
- 确认入库（更新状态+增加库存+记录日志，原子操作）
- 取消进货单（更新状态+减少库存+记录日志，原子操作）

## 六、MyBatis XML 关键SQL

### 6.1 进货单列表查询（含供应商名称）

```xml
<select id="selectByPage" resultType="PurchaseOrderVO">
    SELECT po.*, s.name AS supplier_name, u.real_name AS operator_name
    FROM purchase_order po
    LEFT JOIN supplier s ON po.supplier_id = s.id
    LEFT JOIN sys_user u ON po.user_id = u.id
    <where>
        <if test="orderNo != null and orderNo != ''">
            AND po.order_no LIKE CONCAT('%', #{orderNo}, '%')
        </if>
        <if test="supplierId != null">
            AND po.supplier_id = #{supplierId}
        </if>
        <if test="status != null">
            AND po.status = #{status}
        </if>
        <if test="startDate != null">
            AND po.order_date >= #{startDate}
        </if>
        <if test="endDate != null">
            AND po.order_date <= #{endDate}
        </if>
    </where>
    ORDER BY po.create_time DESC
</select>
```

### 6.2 进货单详情（含明细）

```xml
<select id="selectOrderDetail" resultType="PurchaseOrderVO">
    SELECT po.*, s.name AS supplier_name, u.real_name AS operator_name
    FROM purchase_order po
    LEFT JOIN supplier s ON po.supplier_id = s.id
    LEFT JOIN sys_user u ON po.user_id = u.id
    WHERE po.id = #{id}
</select>

<select id="selectItemsByOrderId" resultType="PurchaseItemVO">
    SELECT poi.*, p.name AS product_name, p.specification, un.name AS unit_name
    FROM purchase_order_item poi
    LEFT JOIN product p ON poi.product_id = p.id
    LEFT JOIN unit un ON p.unit_id = un.id
    WHERE poi.order_id = #{orderId}
</select>
```

### 6.3 更新库存

```xml
<update id="increaseStock">
    UPDATE inventory 
    SET current_stock = current_stock + #{quantity}
    WHERE product_id = #{productId}
</update>

<update id="decreaseStock">
    UPDATE inventory 
    SET current_stock = current_stock - #{quantity}
    WHERE product_id = #{productId} AND current_stock >= #{quantity}
</update>
```

## 九、注意事项

1. 进货单创建和确认入库可以分两步，也可以合并为一步（直接入库），根据业务需求选择。本文档设计为分两步。
2. 确认入库和取消操作必须使用 `@Transactional` 注解保证数据一致性。
3. 取消已入库的进货单时，需检查库存是否充足（避免库存变为负数）。
4. 进货单号生成需考虑并发场景，建议使用数据库序列或Redis自增保证唯一性。
5. 库存变动日志是重要的审计数据，所有库存变更都必须记录。
6. 供应商删除前必须检查是否有关联的进货单，防止数据丢失。
