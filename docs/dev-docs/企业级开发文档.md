## 第一章 项目概述

### 1.1 项目背景

农资进销存管理系统是面向农业物资流通领域的专业管理软件，旨在为农资经销商、零售商、仓库管理员及系统管理员提供全面的信息化管理解决方案。系统实现农资（种子、化肥、农药、农膜等）从采购、库存到销售的全流程数字化管理。

### 1.2 项目目标

1. **业务目标**
   - 实现农资商品全生命周期管理
   - 提供精准的库存预警和统计分析
   - 优化供应链管理流程
   - 提升企业运营效率和决策能力

2. **技术目标**
   - 构建高性能、可扩展的系统架构
   - 实现前后端分离的现代化开发模式
   - 确保系统安全性和数据完整性
   - 支持多终端访问和响应式设计

### 1.3 系统范围

| 功能模块 | 描述 | 优先级 |
|----------|------|--------|
| 用户与权限管理 | 用户注册、登录、角色权限控制 | P0 |
| 农资产品管理 | 产品CRUD、分类管理、单位管理 | P0 |
| 进货与供应商管理 | 采购订单、供应商管理、进货入库 | P0 |
| 销售与客户管理 | 销售订单、客户管理、销售出库 | P0 |
| 库存管理 | 库存查询、库存预警、库存盘点 | P0 |
| 统计报表 | 销售报表、进货报表、库存报表、利润分析 | P1 |

### 1.4 用户角色定义

| 角色代码 | 角色名称 | 职责描述 | 权限范围 |
|----------|----------|----------|----------|
| ADMIN | 系统管理员 | 负责用户管理、基础数据配置、系统维护 | 全部功能 |
| DEALER | 经销商 | 管理进货与供应商，录入进货订单 | 进货管理、供应商管理、库存查看 |
| RETAILER | 零售商 | 销售开单，管理农户客户信息 | 销售管理、客户管理、库存查看 |
| WAREHOUSE | 仓库管理员 | 查看库存、处理出入库、库存盘点 | 库存管理、库存盘点、库存日志 |

### 2.3 分层架构说明

系统采用经典的四层架构设计，各层职责清晰，便于维护和扩展：

#### 2.3.1 表现层（Presentation Layer）
- **技术实现**：Vue 3 + Element Plus
- **主要职责**：
  - 用户界面展示和交互
  - 前端路由管理
  - 表单验证
  - API请求封装

#### 2.3.2 控制器层（Controller Layer）
- **技术实现**：Spring MVC RestController
- **主要职责**：
  - 接收HTTP请求
  - 参数校验和转换
  - 调用业务逻辑层
  - 返回统一响应格式

#### 2.3.3 业务逻辑层（Service Layer）
- **技术实现**：Spring Service
- **主要职责**：
  - 实现核心业务逻辑
  - 事务管理
  - 数据组装和转换
  - 业务规则校验

#### 2.3.4 数据访问层（Mapper Layer）
- **技术实现**：MyBatis Mapper
- **主要职责**：
  - 数据库CRUD操作
  - SQL映射管理
  - 数据持久化

## 第四章 接口设计规范

### 4.1 RESTful API设计原则

1. **URL命名规范**
   - 使用名词复数形式：`/api/products`、`/api/orders`
   - 使用小写字母和连字符：`/api/purchase-orders`
   - 避免动词：使用HTTP方法表示操作

2. **HTTP方法使用**
   - `GET`：查询资源
   - `POST`：创建资源
   - `PUT`：更新资源（全量更新）
   - `PATCH`：部分更新
   - `DELETE`：删除资源

3. **状态码规范**
   - `200`：成功
   - `201`：创建成功
   - `400`：请求参数错误
   - `401`：未授权（未登录）
   - `403`：禁止访问（权限不足）
   - `404`：资源不存在
   - `500`：服务器内部错误

### 4.2 统一响应格式

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

**响应码说明**：

| 响应码 | 说明 |
|--------|------|
| 200 | 操作成功 |
| 400 | 请求参数错误 |
| 401 | 未登录或Token过期 |
| 403 | 权限不足 |
| 500 | 服务器内部错误 |

    // 处理错误
    return Promise.reject(new Error(res.message))
  }
  return res
})

export default service
```

## 第九章 开发规范

### 9.1 代码规范

#### 9.1.1 Java代码规范

1. **命名规范**
   - 类名：大驼峰（PascalCase）
   - 方法名、变量名：小驼峰（camelCase）
   - 常量：全大写下划线分隔（UPPER_SNAKE_CASE）
   - 包名：全小写

2. **注释规范**
   - 类、接口：必须添加JavaDoc注释
   - 公共方法：必须添加JavaDoc注释
   - 复杂业务逻辑：添加行内注释

3. **代码格式**
   - 缩进：4个空格
   - 大括号：换行风格
   - 行长度：不超过120字符

#### 9.1.2 前端代码规范

1. **Vue组件规范**
   - 组件名：多单词，大驼峰
   - Props定义：必须指定类型和默认值
   - 事件命名：kebab-case

2. **JavaScript规范**
   - 使用ES6+语法
   - 优先使用const，其次let
   - 使用箭头函数
   - 使用模板字符串

```

### 11.3 常见问题
