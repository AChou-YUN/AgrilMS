# 阶段2：用户与权限管理

## 一、阶段目标

实现系统的用户认证（登录/注册）与权限控制，支持四种角色（系统管理员、经销商、零售商、仓库管理员）的访问控制，完成用户管理的CRUD功能。

**预计工期：2天**

**前置条件：** 阶段1完成，数据库表和实体类、Mapper已就绪。

---

## 二、功能需求

### 2.1 用户登录
- 用户输入用户名和密码进行登录
- 登录成功返回JWT Token，后续请求携带Token进行身份验证
- 被禁用的用户无法登录（status=0）

### 2.2 用户注册
- 新用户注册，填写用户名、密码、真实姓名、手机号等信息
- 用户名唯一性校验
- 密码使用BCrypt加密存储
- 注册时可选择角色（或由管理员分配）

### 2.3 用户信息管理
- 系统管理员可查看所有用户列表（分页）
- 系统管理员可编辑用户信息、启用/禁用用户
- 系统管理员可为用户分配角色
- 用户可查看和修改自己的基本信息（个人中心）
- 用户可修改自己的密码

### 2.4 权限控制
- 基于角色的访问控制（RBAC）
- 不同角色可访问的接口不同
- 通过JWT拦截器统一校验Token和权限

## 五、请求/响应DTO设计

### 5.1 登录请求

```java
@Data
public class LoginRequest {
    @NotBlank(message = "用户名不能为空")
    private String username;
    @NotBlank(message = "密码不能为空")
    private String password;
}
```

### 5.2 登录响应

```java
@Data
public class LoginResponse {
    private Long userId;
    private String username;
    private String realName;
    private String token;
    private List<String> roles; // 角色标识列表
}
```

### 5.3 注册请求

```java
@Data
public class RegisterRequest {
    @NotBlank(message = "用户名不能为空")
    @Size(min = 3, max = 50, message = "用户名长度3-50位")
    private String username;
    @NotBlank(message = "密码不能为空")
    @Size(min = 6, max = 20, message = "密码长度6-20位")
    private String password;
    private String realName;
    private String phone;
    private String email;
}
```

### 5.4 用户查询请求

public class UserQueryRequest {

    private String realName;

## 六、核心代码结构

### 6.1 JWT工具类

```
util/JwtUtil.java
```

主要方法：
- `generateToken(Long userId, String username, List<String> roles)` — 生成Token
- `parseToken(String token)` — 解析Token
- `validateToken(String token)` — 验证Token有效性
- `getUserIdFromToken(String token)` — 从Token中获取用户ID

**配置项（application.yml）：**
```yaml
jwt:
  secret: your-256-bit-secret-key-here-change-in-production
  expiration: 86400000  # Token有效期：24小时（毫秒）
```

### 6.2 密码工具类

```
util/PasswordUtil.java
```

使用Spring Security的BCryptPasswordEncoder：
- `encode(String rawPassword)` — 加密密码
- `matches(String rawPassword, String encodedPassword)` — 校验密码

### 6.3 登录拦截器

```
interceptor/LoginInterceptor.java
```

- 从请求头中获取 `Authorization: Bearer {token}`
- 验证Token有效性
- 将用户信息存入 `ThreadLocal` 或 `request attribute`
- 白名单路径不拦截：`/api/auth/login`、`/api/auth/register`

### 6.4 权限拦截器

```
interceptor/AuthInterceptor.java
```

- 基于自定义注解 `@RequireRole({"ADMIN", "DEALER"})` 进行权限校验
- 从ThreadLocal获取当前用户角色
- 校验是否具有访问权限

### 6.5 自定义权限注解

```java
@Target({ElementType.METHOD, ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
public @interface RequireRole {
    String[] value();
}
```

### 6.6 当前用户上下文

```java
public class UserContext {
    private static final ThreadLocal<Long> currentUser = new ThreadLocal<>();
    
    public static void setUserId(Long userId) { currentUser.set(userId); }
    public static Long getUserId() { return currentUser.get(); }
    public static void clear() { currentUser.remove(); }
}
```

## 七、拦截器注册配置

```java
@Configuration
public class WebMvcConfig implements WebMvcConfigurer {
    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        // 登录拦截器
        registry.addInterceptor(loginInterceptor)
                .addPathPatterns("/api/**")
                .excludePathPatterns("/api/auth/login", "/api/auth/register");
        
        // 权限拦截器
        registry.addInterceptor(authInterceptor)
                .addPathPatterns("/api/**");
    }
}
```

### 8.2 主要业务逻辑

**登录流程：**
1. 根据用户名查询用户
2. 校验用户状态是否启用
3. 校验密码（BCrypt）
4. 查询用户角色列表
5. 生成JWT Token
6. 返回登录响应

**注册流程：**
1. 校验用户名唯一性
2. 加密密码
3. 插入用户记录
4. 分配默认角色
5. 创建默认库存记录（可选）

## 九、验证标准

| 验证项 | 验证方法 |
|--------|----------|
| 登录功能 | 使用正确用户名密码登录，获取Token |
| Token认证 | 携带Token访问受保护接口，返回200 |
| Token过期 | 使用过期Token访问，返回401 |
| 权限控制 | 经销商访问管理员接口，返回403 |
| 用户CRUD | 管理员可正常增删改查用户 |
| 密码加密 | 数据库中密码为BCrypt格式 |
| 注册功能 | 新用户注册成功，默认角色已分配 |

## 十一、注意事项

1. JWT密钥必须足够复杂（至少256位），生产环境应通过环境变量配置。
2. Token过期时间建议设为24小时，可根据需要调整。
3. 用户名和密码需进行基本的格式校验（长度、特殊字符等）。
4. 删除用户时建议采用逻辑删除（设置status=0）而非物理删除。
5. BCrypt加密每次生成的密文不同，校验时使用BCryptPasswordEncoder.matches()方法。
6. 拦截器中Token解析失败应返回统一的401错误格式。
